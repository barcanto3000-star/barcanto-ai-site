# Barcanto Product Direction

## Core promise

Start with one useful service. Add more skills only when the first service proves valuable.

Barcanto is a modular AI service platform for small businesses—not a single chatbot and not a collection of vague AI features.

## MVP starting point

**Skill 1: Inbox Cleanup**

- Connect an email account with explicit permission.
- Sort noise from messages that need attention.
- Suggest organization rules before changing anything.
- Keep deletion and outbound replies behind human approval.
- Show a clear activity history.

The first commercial goal is to validate whether real customers understand, want, and will pay for this service before building the broader platform.

## Modular skills

Each service should be independently enabled, permissioned, tested, and priced.

Planned examples:

- Smart reminders and follow-ups
- Quote/proposal drafts
- Birthday and customer-care messages
- Invoice preparation and payment follow-ups
- File delivery and sharing
- Business-specific custom tasks

## Customer experience

1. Create a business account.
2. Complete short, problem-focused onboarding.
3. Enable one starting skill.
4. Connect only the account and permission that skill needs.
5. Review activity and results.
6. Unlock another skill when useful.
7. Introduce a dedicated AI agent after the core workflows are proven.

## Agent boundaries

A business's agent should:

- operate inside a separate customer workspace;
- use only purchased and enabled skills;
- respect account-specific data and session boundaries;
- expose a clear activity history;
- require human approval for sensitive actions;
- never gain blanket access merely because another skill was enabled.

## Build order

1. Validate the inbox-cleanup offer.
2. Build minimum account and onboarding flow.
3. Create a shared skill and permission framework.
4. Launch Inbox Cleanup as Skill 1.
5. Add one complementary skill based on customer feedback.
6. Add the broader custom agent after repeated workflows are understood.

## Website role

The public site should explain the starting offer in plain language, demonstrate the modular toolkit, make permissions understandable, and collect early-access conversations. It should not pretend the full application already exists.
